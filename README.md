# Secure Metadata Embedding in Reversible Data Hiding for Encrypted Medical Images

## Overview

Medical images often need to be stored or transmitted alongside associated information, such as patient identifiers, scan identifiers, and examination dates. Protecting this metadata while preserving the integrity of the original medical image is an important challenge in healthcare data security.

This project extends a **Reversible Data Hiding in Encrypted Medical Images (RDHEMI)** framework with a secure metadata embedding and extraction mechanism. It combines the underlying reversible data-hiding pipeline with **AES-256-GCM authenticated encryption** to protect metadata embedded in the reserved space of an encrypted medical image.

The primary objective is to enable encrypted medical metadata to be embedded and recovered while maintaining the ability to reconstruct the original image exactly.

The project builds upon an existing RDHEMI implementation based on Huffman Tree Coding and Count-Encryption. The additional work focuses on secure metadata integration, validation, automated testing, and multi-image experimental evaluation.

## Key Features

- **Encrypted metadata protection:** Uses AES-256-GCM to provide confidentiality and authentication for metadata.
- **Metadata validation:** Validates the structure and required fields of metadata before serialization.
- **Metadata embedding:** Embeds encrypted metadata into the reserved space generated by the RDHEMI pipeline.
- **Metadata extraction:** Extracts the embedded payload and decrypts it to recover the original metadata.
- **Reversible image restoration:** Preserves the original framework's image-recovery functionality.
- **Automated testing:** Includes unit tests for metadata validation and cryptographic operations.
- **Multi-image evaluation:** Executes the evaluation notebook on multiple medical images and records results in CSV format.

## System Architecture

The system follows two related processing paths: reversible image encryption and recovery, and encrypted metadata embedding and extraction.

```text
                Medical Image
                      |
                      v
           Prediction Error Processing
                      |
                      v
              Tree-Based Coding
                      |
                      v
             Count Encryption (CE)
                      |
                      v
             Reserved Space (τ)
                      |
                      + <---- Encrypted Metadata Payload
                      |                 ^
                      v                 |
             Marked Encrypted Image     |
                      |          Metadata Validation
                      v                 ^
             Payload Extraction         |
                      |                 |
                      v                 |
             AES-GCM Decryption --------+
                      |
                      v
             Recovered Metadata

       Original Image Recovery is performed
       using the underlying RDHEMI procedure.
```

The metadata encryption key is separate from the key used by the underlying RDHEMI image-processing pipeline.

## Metadata Security

The metadata protection module uses AES-256-GCM authenticated encryption.

The processing sequence is:

1. Validate the metadata against the expected schema.
2. Serialize the metadata into a compact JSON representation.
3. Encrypt the serialized metadata using AES-256-GCM.
4. Embed the resulting encrypted payload into the reserved space of the encrypted image.
5. Extract the payload from the marked encrypted image.
6. Authenticate and decrypt the payload.
7. Deserialize the plaintext and verify that the recovered metadata matches the original.

AES-GCM provides confidentiality and authentication for the encrypted metadata. It does not, by itself, establish the security of the entire image-encryption or data-hiding framework.

## Preliminary Experimental Results

The metadata embedding and recovery pipeline was executed on five medical images.

| Metric | Observed result |
|---|---:|
| Images evaluated | 5 |
| Reserved space reported by the implementation | 1,489,834 bits per run |
| Encrypted metadata payload | 912 bits |
| Exact metadata recovery | 5/5 (100%) |
| Pixel-perfect image restoration | 5/5 (100%) |
| Restoration mean squared error (MSE) | 0.0 for all five images |
| Successful notebook executions | 5/5 |

These results demonstrate successful end-to-end execution for the five tested images, including metadata recovery and exact image restoration.

The evaluation is preliminary. Larger experiments are needed to establish performance across diverse images, quantify execution time and embedding capacity, and assess security under relevant attack models. The reported reserved-space value should also be validated across images with different characteristics.

## Running the Tests

Create and activate a Python virtual environment, then install the project:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
python -m pip install pytest
```

Run the automated tests:

```bash
python -m pytest -q
```

The notebook and multi-image evaluation script also require the dependencies used by the RDHEMI pipeline and MedMNIST dataset loader.

To run the multi-image experiment from the project root:

```bash
python -m pip install nbclient nbformat
python scripts/evaluate_five.py
```

The script executes the evaluation notebook for five sample indices and writes the results to:

```text
results/multi_image_eval.csv
```

The `results/` directory is excluded from version control by the current `.gitignore`; preserve or export the CSV separately if you need to share the experiment results.

## Research Foundation

This project builds upon the RDHEMI approach described in the following research paper:

**Reversible Data Hiding in Encrypted Medical Images Based on Huffman Tree Coding and Count-Encryption**

[IEEE Xplore — Research paper](https://ieeexplore.ieee.org/document/11125529)

The original research provides the foundation for the reversible data-hiding pipeline. This project focuses on integrating authenticated encryption for metadata and evaluating the combined workflow.
